# Method, semantics and evidence

Pixel Witness enumerates 176 component-editing recipes: 16 selectors × 11 actions. It retains every recipe matching every supplied before/after example exactly. A suggested witness maximizes Shannon entropy of predicted outputs under a uniform distribution over surviving recipes, with ties favoring the first witness-pool input. This is a query-selection heuristic, not calibrated confidence. Batch output is available for an input only if all surviving recipes agree on its entire output. Zero candidates and competing predictions both abstain. No splitting witness in the finite pool does not establish global equivalence.

## Exact editing semantics

Inputs are flat arrays of 64 integers, palette 0–3, with zero as background. Components are nonzero, same-color, four-connected cells; diagonal adjacency and touching different colors do not merge components. Selection uses the original grid.

The selectors are all components; largest/smallest by pixel count (including all ties); border-touching/interior; color 1/2/3; singleton/non-singleton; wider-than-tall/taller-than-wide bounding boxes (squares are neither); and top/bottom/left/right canvas-edge touching. Edge selectors mean actual canvas edges, not the topmost/bottommost/leftmost/rightmost component in an interior drawing.

Actions are recolor to 1/2/3, erase, add outline in 1/2/3, or move one pixel up/down/left/right. Outlines fill only originally empty four-neighbor cells, clipped to the canvas, never overwriting original artwork. All selected components translate simultaneously. Any selected pixel moving outside the canvas or colliding with unselected original artwork cancels the entire move. Selected source cells may be destinations. Outputs are new arrays; no sequential selection cascades occur.

Syntactically distinct recipes remain distinct even when observed outputs coincide, so entropy depends on the chosen grammar. Recipe JSON accepts only known language members; it contains no executable code. Session JSON is a bounded data-only codec accepting versions 1/2 and exporting version 2. It validates examples and batch inputs and recomputes derived results rather than trusting imported claims.

## Evaluation

`protocol.json` records the fixed current protocol and seeds; `metrics.json` records per-target results. This package does not independently establish when the protocol was first written. Deterministic reproduction preserves all original protocol, metrics and generator bytes.

All 176 in-grammar targets are retained. The benchmark reports 3,372 evidence checks without failure and 1,408 heldout target/input cases: 1,090 agreed outputs, 318 abstentions, zero false agreed outputs. Targets and expected benchmark outputs are generated by the same interpreter being tested: this establishes internal consistency under the in-grammar assumption, not independent proof of intended semantics. Contradiction and a known impossible empty-to-new-pixel edit each yield zero candidates.

For 44 deterministic targets and a 32-grid witness pool, entropy resolves 44/44 with mean capped queries 0.8636363636363636 (maximum 3); seeded random resolves 43/44 with mean 1.5454545454545454 (maximum 6); fixed order resolves 44/44 with mean 1.2954545454545454 (maximum 6). The cap is six and the random unsolved case remains included at the cap. These are descriptive finite-pool comparisons, not statistical superiority or global program equivalence.

`test_semantics.mjs` separately contains literal, hand-authored expected grids and component memberships, without calling the interpreter to generate expected output. It covers every selector and action with small synthetic cases. The author and independent review suites additionally test validation, state transitions, exports, source/bundle parity and presentation contracts. None substitutes for a real editing corpus, measured productivity, mobile devices or assistive-technology testing.

## Prior art and implementation attribution

This is symbolic inductive program synthesis and active query selection, not new synthesis machinery. Relevant prior work and alternatives include:

- ImageEye: https://arxiv.org/abs/2304.03253
- SmartLabel: https://arxiv.org/abs/2508.15750
- Pattern Analogies: https://bardofcodes.github.io/patterns/
- Aseprite CLI and scripting as practical batch-editing alternatives.

The proposed practical distinction is a small browser-native editing workflow that exposes competing explanations, visual questions and per-input abstention. The implementation, packaging and tests were AI-assisted. There is no pretrained model, remote AI call, API key or dynamically generated executable code in the application runtime.
